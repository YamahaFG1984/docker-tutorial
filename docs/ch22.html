接下来学什么

Kubernetes

理解了 Docker，Kubernetes 就是最自然的下一步。它的思想和 Swarm 很像（期望状态、调和、服务、滚动更新），但范围更大、社区更活跃。 你用 Docker 构建的镜像可以直接在 Kubernetes 上运行。Docker Desktop 自带一键启用的 Kubernetes（新版本默认用 kind 创建集群），非常适合入门。 原书作者还写了《Quick Start Kubernetes》和《The Kubernetes Book》，可以作为延伸阅读。

AI 编程助手与 Docker Sandboxes

2026 年，Docker 推出了 Docker Sandboxes（docker sbx）：为 Claude Code、Codex、Gemini CLI 等 AI 编程助手提供基于 microVM 的隔离环境。 每个会话运行在独立的轻量虚拟机里，只挂载你的项目目录，助手可以放心地安装软件、甚至运行自己的容器，而不会影响你的主机。 这正是第 1 章“虚拟机 vs 容器”取舍的新应用：需要更强隔离时，用 microVM；需要轻量高效时，用容器。

参与社区

云原生社区里有很多乐于助人的人。可以加入线上的 Docker 群组和讨论，或者搜索本地的 Docker / 云原生 Meetup。 Docker 官方文档是最权威、更新最及时的参考资料，遇到问题先查它。

术语表

这里收录了全书最常用的 Docker 与容器术语（基于原书术语表翻译整理，并补充了 2026 年的新概念）。

术语解释
AI 加速硬件GPU、NPU、TPU 等能加速 AI 模型执行（推理）的硬件
API应用编程接口。Docker 的所有资源都定义在 Docker API 中，它是 RESTful 的，由 Docker 守护进程提供
基础镜像 Base image所有镜像的第一层，由 Dockerfile 的 FROM 指令创建，通常包含应用所需的最小操作系统结构
BakeDocker 的高层构建编排工具（docker buildx bake），用一个文件声明多个构建目标并行构建；Compose v5 的构建也委托给它
构建 Build按 Dockerfile 中的指令逐步创建新镜像的过程
Build Cloud在 Docker 云端基础设施上执行快速构建的订阅服务，团队可共享构建缓存
BuildKitDocker 的构建引擎，实现高级缓存、多阶段构建、多架构构建等功能
BuildxDocker 的构建客户端（CLI 插件），支持 BuildKit 全部新特性；自 Engine 23.0 / Desktop 4.19 起为默认
CapabilityLinux 内核把 root 权限拆分成的细粒度权限单元，Docker 用它实现最小权限
cgroups 控制组Linux 内核功能，Docker 用它限制容器使用的 CPU、内存、磁盘、网络资源
云原生 Cloud native一种设计、构建和运行现代应用的方式。作者认为能自我修复、按需伸缩、滚动更新、版本回滚的应用就是云原生应用
集群存储 Cluster storeDocker Swarm 保存集群和应用状态的分布式数据库，基于 etcd，自动加密并复制到所有管理节点
CNM 容器网络模型Docker 网络的设计规范，定义沙箱、端点、网络三个构件；libnetwork 是其实现
Compose定义、部署和管理多容器应用的开放规范；Docker 实现了它并提供 docker compose 命令
容器 Container一组被组织成看起来像普通操作系统的内核命名空间。每个容器运行一个应用，比虚拟机更小、更快、更便携
容器化 Containerize把应用及其所有依赖打包成容器镜像的过程
容器运行时每个节点上负责拉取镜像、启停容器等底层操作的软件。Docker 用两层运行时：高层的 containerd 管理生命周期，低层的 runc 与内核打交道
containerd行业标准的容器运行时，被 Docker 和大多数 Kubernetes 集群使用，由 Docker 公司捐赠给 CNCF。读作 “container dee”
containerd 镜像存储由 containerd 的 snapshotter 管理镜像的存储方式，Docker Engine 29 起为全新安装的默认值，原生支持多平台镜像和证明
期望状态 Desired state集群和应用“应该是什么样子”，比如某服务应有 5 个监听 8080 端口的副本。调和的依据
摘要 Digest根据镜像内容计算出的加密哈希，不可变，可以精确指定一个镜像
Docker让容器化应用变得简单的平台：构建镜像、运行和管理独立容器及多容器应用
Docker Content Trust（DCT）基于 Notary v1 的旧镜像签名机制，已退役：Engine 29 从 CLI 中移除，Notary 服务于 2026 年 12 月 8 日关闭。替代品是 Cosign / Notation
Docker DebugCLI 插件，为不带调试工具的精简镜像和容器提供带工具箱的调试 shell
Docker DesktopLinux、Mac、Windows 上的桌面应用，带图形界面和镜像管理、Model Runner 等高级功能
Docker Hardened Images（DHI）Docker 维护的精简、加固、持续打补丁的基础镜像，2025 年 12 月起免费
Docker Hub高性能、符合 OCI 标准的公共镜像仓库
Docker, Inc.Docker 平台背后的美国科技公司
docker initCLI 插件，分析项目并生成高质量的 Dockerfile、.dockerignore 和 Compose 文件
Docker Model Runner（DMR）Docker 运行本地 AI 模型的原生工具，在容器之外直接使用宿主机硬件，提供 OpenAI 等兼容端点
Docker Sandboxes基于 microVM 为 AI 编程助手提供隔离开发环境的产品（docker sbx）
Docker ScoutDocker 的漏洞扫描与供应链分析服务，集成在 CLI、Docker Hub 等处
Dockerfile告诉 Docker 如何把应用构建成镜像的纯文本指令文件
etcdDocker Swarm 使用的开源分布式数据库
GGUF存储 LLM 权重和元数据的二进制文件格式
镜像 Image包含应用代码、所有依赖和启动元数据的只读包，也叫 OCI 镜像、容器镜像、Docker 镜像
Ingress 网络所有 Swarm 集群上都有的隐藏网络，用于向外部客户端发布服务（路由网格）
内核命名空间 NamespaceLinux 内核功能，Docker 用它把容器与宿主机进程及其他容器隔离开
层 Layer镜像由层堆叠而成，每层包含对下层的修改；上层文件会遮盖下层同名文件
libcontainer / libnetworkDocker 用来创建容器（通过 runc）/ 创建和管理容器网络的 Go 库
llama.cpp / vLLM开源的 LLM 推理引擎。前者轻量、能在消费级 CPU 上运行，后者面向 GPU 上的高吞吐生产场景；都是 DMR 的可选后端
大语言模型 LLM能参与人类对话、生成类人回答的 AI 模型
Manifest（OCI 清单）描述镜像、模型等 OCI 制品的配置和层的 JSON 文档
Manifest list / Image index一个标签下支持哪些架构的列表，是多架构镜像的基础
微服务 Microservices现代应用的设计模式：每个功能作为独立的小应用（容器）开发，通过 API 协同工作
多架构构建用一条 docker build 命令为多个平台/架构构建镜像
多阶段构建一个 Dockerfile 中有多个 FROM，后面的阶段用 COPY --from 只拿需要的产物，得到很小的生产镜像
观察状态 Observed state集群和应用当前的实际状态。Swarm 总在努力让它等于期望状态
OCI 开放容器倡议负责制定镜像、运行时、分发等底层容器标准的轻量治理组织
OpenAI 兼容端点按 OpenAI API 规范接收请求、返回响应的 API 服务
编排器 Orchestrator部署和管理应用的软件，如 Docker Swarm 和 Kubernetes：保持应用健康、扩缩容等
Overlay 网络横跨多个 swarm 节点的扁平二层网络，基于 VXLAN；不同主机上的容器可直接通信
Push / Pull把镜像上传到 / 从仓库下载
量化 Quantization在不过多牺牲准确度的前提下减小 AI 模型体积和内存需求的方法
调和 Reconciliation持续观察应用状态、确保观察状态等于期望状态的过程
仓库 Registry / 镜像库 Repository集中存放镜像的地方 / 仓库中存放一组相关镜像的区域，可按库设置权限
runcOCI 运行时规范的参考实现，Docker 的低层运行时，读作 “run see”
SBOM软件物料清单：镜像中所有软件包及版本的列表，漏洞扫描和供应链安全的基础
seccompLinux 内核功能，Docker 用它限制容器可用的系统调用
Secret 机密Docker 在运行时安全地向容器注入敏感数据的方式
Service 服务Docker Swarm 的对象，为容器增加自我修复、扩缩容、滚动更新和回滚能力
Sigstore / Cosign现代的 OCI 原生镜像签名方案，支持基于身份的无密钥签名，是 DCT 的主要替代品
Spin让构建和运行 Wasm 应用变得简单的框架，最初由 Fermyon 创建
SwarmDocker 原生的编排平台，Kubernetes 的轻量替代
卷 Volume容器存放需要保留的重要数据的地方，可以独立于容器创建和删除
Wasm（WebAssembly）一种新的虚拟指令集架构，比传统容器更小、更快、更安全、更便携，可在任何有 Wasm 运行时的地方运行
YAML一种数据序列化格式，Compose 文件用它编写；它是 JSON 的超集
