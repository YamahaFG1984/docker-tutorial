第 3 章

安装 Docker

获取 Docker 的方式有很多。本章介绍三种：Docker Desktop（强烈推荐，桌面电脑首选）、 Linux 服务器安装（生产环境的标准做法）和 Multipass 虚拟机（想要多节点实验环境时用）。

本章目标

  • 根据自己的电脑选择合适的安装方式
  • 在 Windows / Mac 上装好 Docker Desktop，并理解它背后的 Linux 虚拟机
  • 用官方软件源在 Ubuntu 上安装 Docker Engine
  • 学会用 docker version 和 docker info 验证安装
  • 知道 docker 用户组的安全含义，以及 rootless 模式

先选一种安装方式

作者强烈推荐 Docker Desktop，本教程的大部分示例也都可以用它完成。 但 Docker Desktop 只提供单个 Docker 节点，所以 Swarm 和 overlay 网络章节需要多台机器，届时再用 Multipass 或 Linux 服务器。

Docker Desktop

Docker Desktop 是 Docker 公司出品的桌面应用，是使用容器最方便的方式。一次安装你就能得到： Docker Engine、漂亮的图形界面、最新的 CLI 插件（Buildx、Compose、Scout、Debug、Model Runner……）、扩展市场， 甚至还能一键启动一个 Kubernetes 集群来学习。

ⓘ 许可证提醒

个人、教育和小企业免费。如果在工作中使用且公司员工超过 250 人或年收入超过 1000 万美元，需要付费订阅（见第 2 章）。

在 Windows 上安装

前置条件：

  • 64 位 Windows 10（22H2 及以上）或 Windows 11
  • 在 BIOS 中开启硬件虚拟化支持（大多数新电脑默认已开启；修改 BIOS 请务必小心）
  • WSL 2（Windows Subsystem for Linux 2）

安装步骤：

  1. 前往 Docker 官方文档的 Windows 安装页，下载安装程序。
  2. 运行安装程序，出现提示时选择使用 WSL 2 后端。
  3. 安装完成后，从开始菜单手动启动 Docker Desktop。任务栏上的小鲸鱼图标停止动画，就表示启动完成。
  4. 打开终端（PowerShell 或 Windows Terminal），运行 docker version 验证。

Windows 专业版和企业版上的 Docker Desktop 同时支持 Linux 容器和 Windows 容器，可以右键点击系统托盘里的鲸鱼图标， 选择 Switch to Windows containers… 切换。请保持在 Linux 容器模式，本教程所有示例都是 Linux 容器。

在 Mac 上安装

在安装之前，先了解一件重要的事：Docker Desktop for Mac 把守护进程和所有服务端组件装在一台轻量的 Linux 虚拟机里， 然后把 API 无缝暴露给你的 Mac。所以你在 Mac 终端里敲 docker 命令时，根本感觉不到背后有一台隐藏的虚拟机。 这也是为什么 Mac 上的 Docker Desktop 只能跑 Linux 容器 —— 一切都运行在那台 Linux 虚拟机里。

安装方法很简单：前往 官方文档的 Mac 安装页， 根据芯片选择 Apple silicon 或 Intel 版本下载，拖进“应用程序”文件夹，然后启动。 等顶部状态栏的鲸鱼图标停止动画，就可以打开终端使用了。

$ docker version
Client:
 Version:           29.8.0
 API version:       1.54
 OS/Arch:           darwin/arm64
 Context:           desktop-linux
 <Snip>

Server: Docker Desktop 4.92.0
 Engine:
  Version:          29.8.0
  API version:      1.54 (minimum version 1.40)
  OS/Arch:          linux/arm64
 containerd:
  Version:          v2.3.5
 runc:
  Version:          1.3.x
 docker-init:
  Version:          0.19.0

注意看 Client 的 OS/Arch 是 darwin/arm64，而 Server 的是 linux/arm64。 这正是图 3-2 的证据：客户端是原生 Mac 程序，跑在 Darwin 内核上；引擎跑在那台 Linux 虚拟机里。 （第 1 章练习第 3 题的答案就在这里。）Windows 上也一样，Server 显示 linux/amd64，因为默认假设你要跑 Linux 容器。

ⓘ 版本号不必完全一致

书中和教程里的版本号只是示例。只要 Client 和 Server 两部分都有输出，就说明 Docker 工作正常。

✨ 最新变化：最低 API 版本的一次反复

Docker Engine 29.0 曾把服务端支持的最低 API 版本从 1.24 一下子提高到 1.44（对应 Docker 25.0），导致不少老客户端和第三方工具报 “client version is too old”。29.3 起又放宽回 1.40（对应 Docker 19.03），也就是上面输出里的 minimum version 1.40。 如果你遇到这个报错，升级客户端或工具，或者把引擎升级到 29.3 以上即可。

在 Linux 上安装 Docker Engine

在 Linux 服务器上，标准做法是从 Docker 官方软件源安装 Docker Engine。它开源免费、没有图形界面， 但所有核心功能都有。下面以 Ubuntu 为例（Debian、Fedora、RHEL 等请参考 官方安装文档）。

✨ 与原书不同：不要用 snap 安装

原书用 sudo snap install docker 演示安装。这个 snap 包由 Canonical 打包，版本往往滞后， 而且 snap 的沙箱限制会导致卷挂载等功能出现奇怪问题。Docker 官方推荐使用下面的 apt 软件源方式。 另外，Ubuntu 自带的 docker.io 包也不是 Docker 官方维护的，建议先卸载。

第 1 步：配置官方软件源

# 卸载可能存在的非官方旧包（没装过也没关系）
$ for pkg in docker.io docker-doc docker-compose podman-docker containerd runc; do sudo apt-get remove -y $pkg; done

# 添加 Docker 官方 GPG 密钥
$ sudo apt-get update
$ sudo apt-get install -y ca-certificates curl
$ sudo install -m 0755 -d /etc/apt/keyrings
$ sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
$ sudo chmod a+r /etc/apt/keyrings/docker.asc

# 添加软件源
$ sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF
$ sudo apt-get update

第 2 步：安装

$ sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
    docker-buildx-plugin docker-compose-plugin

# 可选：Docker Model Runner 插件（第 10 章用）
$ sudo apt-get install -y docker-model-plugin

这几个包各司其职：

💡 快速体验用的一键脚本

如果只是在测试机上快速装一个，可以用官方的便捷脚本：curl -fsSL https://get.docker.com | sh。 它会自动完成上面的步骤。但不建议在生产环境使用，因为你没法控制装的是哪个版本。

第 3 步：验证

$ sudo systemctl status docker      # 确认守护进程在运行
$ sudo docker run hello-world       # 跑一个测试容器

Hello from Docker!
This message shows that your installation appears to be working correctly.
<Snip>

第 4 步（可选）：免 sudo 运行

默认情况下每条 docker 命令都要加 sudo。原因是 Docker API 通过一个受保护的 Unix 套接字 /var/run/docker.sock 暴露，只有 root 和 docker 用户组的成员能访问。把自己加入这个组就能免 sudo： 

$ sudo groupadd docker              # 通常安装时已经创建，报“已存在”可忽略
$ sudo usermod -aG docker $USER
$ newgrp docker                     # 或者注销后重新登录
$ docker run hello-world            # 不用 sudo 了
⚠ docker 用户组 ≈ root 权限

能访问 Docker 套接字，就能启动一个挂载了宿主机根目录的特权容器，等于拿到了整台机器的 root 权限。 所以只把你信任的用户加入 docker 组。对安全要求高的环境，可以考虑下面的 rootless 模式。

🔬 深入：Rootless 模式

Rootless 模式让 Docker 守护进程和容器都以普通用户身份运行，即使容器被攻破，攻击者也拿不到宿主机的 root 权限。 安装好 Docker 后，以普通用户运行 dockerd-rootless-setuptool.sh install 即可启用。 代价是有一些限制（比如不能直接绑定 1024 以下的端口、部分网络和存储驱动不可用）。详见 官方文档。

用 Multipass 创建 Docker 虚拟机

如果你用不了 Docker Desktop，或者想要多台装好 Docker 的机器来做集群实验， Multipass 是个好选择。它是 Canonical 出品的免费工具， 能在 Linux、Mac、Windows 上一条命令创建云风格的 Ubuntu 虚拟机。

你只需要记住三条命令：multipass launch、multipass ls、multipass shell。

# 基于预装了 Docker 的 "docker" 镜像创建一台叫 node1 的虚拟机
$ multipass launch docker --name node1

# 查看虚拟机和它的 IP（后面章节会用到 192.168.x.x 这个地址）
$ multipass ls
Name     State     IPv4             Image
node1    Running   192.168.64.37    Ubuntu 24.04 LTS
                   172.17.0.1

# 登录进去
$ multipass shell node1
ubuntu@node1:~$ docker --version

输入 exit 退出虚拟机；不需要时用 multipass delete node1 和 multipass purge 彻底删除。

💡 不想装任何东西？

Play with Docker 提供免费的在线 Docker 实验环境（需要 Docker Hub 账号）， 每次会话 4 小时，可以一键创建多个节点，非常适合第 12–14 章的集群实验。

其他选择

除了 Docker 官方的产品，社区还有一些兼容 Docker CLI 的桌面工具，思路都是“在 Mac / Windows 上跑一台 Linux 虚拟机”：

Podman Desktop

Red Hat 主导，无守护进程、默认 rootless，CLI 与 docker 基本兼容。

Rancher Desktop

SUSE 出品，开源免费，自带 Kubernetes（k3s），可选 dockerd 或 containerd。

OrbStack

macOS 专用，启动快、资源占用低，商业软件（个人免费）。

Colima

macOS / Linux 上的开源命令行工具，轻量，适合喜欢终端的人。

它们都能跑本教程的大部分示例，但 docker debug、docker scout、Model Runner 等 Docker Desktop 独有功能可能不可用。

✨ 最新变化：containerd 镜像存储成为默认

注意上面 Storage Driver 那一行。从 Docker Engine 29 起，全新安装默认使用 containerd 镜像存储 （显示为 driver-type: io.containerd.snapshotter.v1），而不再是传统的 overlay2 图驱动。 从旧版本升级上来的机器会保留原来的设置。containerd 镜像存储原生支持多平台镜像、镜像证明（attestation）等新功能，第 5、6 章会再提到它。

本章小结

  • Docker 几乎可以装在任何地方。桌面电脑首选 Docker Desktop：功能最全、有图形界面、自带各种插件。
  • Docker Desktop 在 Mac 和 Windows 上通过一台隐藏的 Linux 虚拟机运行引擎，所以 Server 的 OS 显示为 linux。
  • Linux 服务器用 官方 apt/dnf 软件源安装 Docker Engine，不推荐 snap 或发行版自带的旧包。
  • 加入 docker 用户组可以免 sudo，但这等同于 root 权限；安全敏感场景考虑 rootless 模式。
  • 需要多节点实验环境时，用 Multipass 或 Play with Docker。

✎ 动手练习

  1. 按照本章内容安装 Docker，运行 docker version，记下 Client 和 Server 的 OS/Arch，解释它们为什么相同或不同。
  2. 运行 docker run hello-world，仔细读一遍输出 —— 它用 4 个步骤解释了刚刚发生了什么，和第 5 章要讲的内容完全对应。
  3. 运行 docker info，找出你的存储驱动（Storage Driver）是什么，以及装了哪些 CLI 插件。
