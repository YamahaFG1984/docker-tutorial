第 15 章

卷与持久化数据

容器被设计成“随时可以丢弃”，可数据库里的订单、用户上传的图片，可不能跟着容器一起丢。 本章讲清楚容器里的数据到底存在哪、什么时候会丢，以及如何用卷（volume）让重要数据活得比容器更久。 最后补充原书没有展开的绑定挂载和 tmpfs，它们在日常开发中同样常用。

本章目标

  • 区分持久化数据与非持久化数据、有状态应用与无状态应用
  • 理解容器可写层的位置和生命周期
  • 会用 docker volume 创建、查看、删除卷，并把卷挂进容器
  • 理解跨节点共享存储时的数据损坏风险
  • 分清卷、绑定挂载、tmpfs 三种挂载方式，以及 -v 与 --mount 的写法

一句话概括

数据分为两种：

💾

持久化数据

你在乎、必须保留的数据：客户记录、财务数据、研究结果、审计数据、某些日志。管理这类数据的应用叫有状态应用。

🗑

非持久化数据

不在乎、不需要保留的数据：临时文件、缓存、草稿。不产生持久数据的应用叫无状态应用。

Docker 对两者都有方案：

  • 对无状态应用，Docker 给每个容器一块跟随容器生命周期的本地存储（可写层），适合放临时数据，容器删除后就没了；
  • 对有状态应用，Docker 提供卷。卷是独立的对象，有自己的生命周期，挂载到容器里使用。删除容器不会删除卷和里面的数据，卷还可以挂到别的容器里。

没有卷的容器

Docker 早期，容器只适合不产生重要数据的无状态应用。但即便是无状态应用，很多也需要一个地方写临时数据。 所以 Docker 创建容器时，会把只读的镜像层堆叠起来，然后在最上面放一层薄薄的本地存储（第 7 章讲过的读写层）：

这一层是容器“可读写”的关键：应用要修改已有文件或添加新文件时，改动都写进这一层，Docker 再把它合并进容器看到的视图里。 但它和容器的生命周期绑定：容器创建时它被创建，容器删除时它被删除。所以它不适合存放需要保留的数据。

★ 容器应该是不可变的

虽然可写层让你能修改运行中的容器，但你永远不应该这样做。应该把容器当作不可变对象：部署后就不再修改。 需要修复或改配置时，创建并测试一个包含改动的新容器，然后用它替换旧容器。 要说明的是：数据库这类应用当然可以修改它管理的数据；但用户和配置工具不应修改容器本身的配置（网络、应用配置等）。

使用卷的容器

应该用卷来处理容器中的持久化数据，三个主要理由：

  1. 卷是独立对象，不和容器的生命周期绑定；
  2. 卷可以映射到专门的外部存储系统；
  3. 不同 Docker 主机上的多个容器可以通过卷访问和共享同一份数据。

流程是：先创建卷，再创建容器，然后把卷挂载进容器的某个目录。写到这个目录的一切都存到卷里。 删掉容器，卷和数据都还在，你甚至可以把这个卷挂到另一个容器里。容器的其他目录仍然使用本地存储中的可写层。

创建和管理卷

卷是 Docker 的一等公民：有专门的 docker volume 子命令，API 里也有卷资源。

$ docker volume create myvol
myvol

$ docker volume ls
DRIVER    VOLUME NAME
local     myvol

$ docker volume inspect myvol
[
    {
        "CreatedAt": "2026-09-22T12:23:14Z",
        "Driver": "local",
        "Labels": null,
        "Mountpoint": "/var/lib/docker/volumes/myvol/_data",
        "Name": "myvol",
        "Options": null,
        "Scope": "local"
    }
]
  • 默认使用内置的 local 驱动创建卷，顾名思义，这种卷只能被同一节点上的容器使用。可以用 -d 指定其他驱动（需要先安装）。
  • Driver 和 Scope 都是 local，说明卷只在这台主机上可用；Mountpoint 显示卷在主机文件系统中的位置。
  • local 驱动会给每个卷在主机的 /var/lib/docker/volumes 下建一个目录。这意味着任何能访问主机的人都能绕过容器直接访问卷的内容 —— 能做到，但不推荐这么做。

删除卷有两种方式：

$ docker volume rm myvol                # 精确删除指定的卷

$ docker volume prune --all             # 删除所有没被容器或服务副本使用的卷，慎用！
WARNING! This will remove all local volumes not used by at least one container.
Are you sure you want to continue? [y/N] y
Deleted Volumes:
myvol

两个命令都不会删除正在被使用的卷。你刚刚创建、查看、删除了一个卷，全程没有涉及任何容器 —— 这证明了卷与容器是解耦的。

ⓘ prune 的 --all

自 Docker Engine 23 起，不加参数的 docker volume prune 只删除匿名卷（没有名字、由 Docker 随机命名的卷），加上 --all 才会连有名字的卷一起删除。

Dockerfile 中的 VOLUME 指令

除了命令行和 Compose 文件，还可以在 Dockerfile 里用 VOLUME <容器内挂载点> 声明卷。有意思的是，Dockerfile 里不能指定主机目录 —— 因为不同主机的目录结构可能不同，写死一个主机上不存在的目录会让构建出问题。所以主机端的位置要在部署时指定；如果部署时什么都不指定，Docker 会自动创建一个匿名卷。

在容器中使用卷

$ docker run -it --name voltainer \
    --mount source=bizvol,target=/vol \
    alpine

--mount 让 Docker 把一个叫 bizvol 的卷挂到容器的 /vol。虽然你并没有叫 bizvol 的卷，命令也成功了，这说明：

  • 指定的卷已存在，Docker 就使用它；
  • 指定的卷不存在，Docker 就创建它。

按 Ctrl+P Ctrl+Q 回到本地 shell，验证卷已被创建、并且在使用中无法删除：

$ docker volume ls
DRIVER    VOLUME NAME
local     bizvol

$ docker volume rm bizvol
Error response from daemon: remove bizvol: volume is in use - [b44d3f82...dd2029ca]

往卷里写点数据：

$ docker exec -it voltainer sh
/ # echo "I promise to write a book review on Amazon" > /vol/file1
/ # cat /vol/file1
I promise to write a book review on Amazon
/ # exit

$ docker rm voltainer -f          # 删除容器
$ docker volume ls                # 卷还在！
DRIVER    VOLUME NAME
local     bizvol

卷还在，所以可以直接在主机上看到它的内容（Docker Desktop 上看不到，因为它在虚拟机里；可能需要 sudo。再次提醒：不推荐直接访问主机上的卷目录，这里只是演示）：

$ sudo cat /var/lib/docker/volumes/bizvol/_data/file1
I promise to write a book review on Amazon

最后，把这个卷挂到一个全新的容器里：

$ docker run -it --name newctr --mount source=bizvol,target=/vol alpine sh
/ # cat /vol/file1
I promise to write a book review on Amazon

恭喜！你创建了卷、写入数据、删除了原来的容器、把卷挂到第二个容器，并验证了数据依然存在。（作者说：如果你真去写了书评，谢谢！没写的话他会哭，但能挺过去 ;-)）

三种挂载方式：卷、绑定挂载、tmpfs

原书只讲了卷，但日常开发中你一定会遇到另外两种挂载方式，这里补上：

卷 volume绑定挂载 bind mounttmpfs
数据在哪Docker 管理的目录主机上你指定的任意路径主机内存
谁管理Docker（docker volume）你自己Docker
容器删除后保留保留（本来就是主机文件）消失
跨平台好（Mac/Windows 上性能也好）依赖主机目录结构仅 Linux
典型用途生产数据：数据库、上传文件开发：把源码挂进容器实时生效；挂配置文件敏感的临时数据、高速缓存

-v 与 --mount 两种写法

-v / --volume：简洁，冒号分隔
# 卷（名字不以 / 或 . 开头）
docker run -v bizvol:/vol alpine
# 绑定挂载（路径）
docker run -v "$(pwd)"/src:/app/src node
# 只读
docker run -v "$(pwd)"/nginx.conf:/etc/nginx/nginx.conf:ro nginx
--mount：啰嗦但清晰（推荐）
docker run --mount type=volume,src=bizvol,dst=/vol alpine
docker run --mount type=bind,src="$(pwd)"/src,dst=/app/src node
docker run --mount type=bind,src="$(pwd)"/nginx.conf,dst=/etc/nginx/nginx.conf,readonly nginx
docker run --mount type=tmpfs,dst=/run/cache alpine
⚠ 两种写法的一个关键差异

用 -v 绑定挂载一个主机上不存在的路径时，Docker 会悄悄帮你创建一个空目录（常常导致“我的配置文件怎么变成了目录”的困惑）； 用 --mount type=bind 则会直接报错。这也是推荐 --mount 的原因之一。

在 Compose 里，两种写法都支持：

services:
  db:
    image: postgres:17
    volumes:
      - pgdata:/var/lib/postgresql/data     # 卷：生产数据
  web:
    build: .
    volumes:
      - ./src:/app/src                      # 绑定挂载：开发时热更新
      - type: tmpfs                         # tmpfs：临时文件
        target: /tmp
volumes:
  pgdata:

备份与恢复卷

卷不能直接“复制”，但可以借助一个临时容器，把卷打包成 tar 文件放到当前目录：

# 备份：挂载卷 + 挂载当前目录，把卷内容打包
$ docker run --rm -v bizvol:/source:ro -v "$(pwd)":/backup alpine \
    tar czf /backup/bizvol.tgz -C /source .

# 恢复到一个新卷
$ docker run --rm -v bizvol-restored:/target -v "$(pwd)":/backup alpine \
    tar xzf /backup/bizvol.tgz -C /target

本章小结

  • 数据分持久化和非持久化两种。每个容器默认都有一块随容器生灭的可写层，适合非持久化数据。
  • 需要保留的数据应该存到卷里。卷是 Docker API 中的一等对象，用 docker volume 独立管理，删除容器不会删除卷里的数据。
  • 第三方卷插件可以把 Docker 接入专门的外部存储系统，实现跨节点共享 —— 但应用必须自己协调并发写入，否则可能损坏数据。
  • 除了卷，还有绑定挂载（适合开发时挂源码和配置）和 tmpfs（内存中的临时数据）。推荐使用含义更明确的 --mount 写法。
  • 卷是 Docker 环境中处理持久化数据的推荐方式。

  2. 用绑定挂载把本地的 index.html 挂到 nginx 的 /usr/share/nginx/html，修改本地文件后刷新浏览器，体会开发时的热更新。
