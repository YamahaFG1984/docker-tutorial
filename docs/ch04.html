第 4 章

第一次上手

理论讲够了，动手吧！本章分两部分：运维视角——拉取镜像、启动容器、进入容器、删除容器； 开发视角——拿到一份源代码，把它构建成镜像，再作为容器运行。两部分都走一遍，你就是半个 DevOps 了。

本章目标

  • 用 docker pull 下载镜像，用 docker images 查看本地镜像
  • 看懂 docker run -d -p --name 每个参数的含义
  • 用 docker exec 进入运行中的容器执行命令
  • 用 docker stop / docker rm 停止并删除容器
  • 用 Dockerfile + docker build 把一个 Node.js 应用容器化并运行

运维视角：运行一个现成的应用

这一部分你将完成：检查 Docker 是否正常 → 下载镜像 → 从镜像启动容器 → 在容器里执行命令 → 删除容器。

① 检查 Docker 是否正常

一次典型的 Docker 安装会把客户端和引擎装在同一台机器上，并配置好它们之间的通信。运行 docker version：

$ docker version
Client:
 Version:           29.8.0            <<--- 客户端信息
 OS/Arch:           darwin/arm64
 <Snip>
Server: Docker Desktop 4.92.0         <<--- 服务端（引擎）信息
 Engine:
  Version:          29.8.0
  OS/Arch:          linux/arm64
 <Snip>

Client 和 Server 都有输出，说明一切正常。如果你在 Linux 上看到 permission denied while trying to connect to the Docker daemon...， 就在命令前加 sudo 再试（或者参考第 3 章把自己加入 docker 组）。

② 下载一个镜像

镜像是包含了运行一个应用所需一切的对象：一个精简的操作系统文件系统、应用本身、以及所有依赖。 如果你做运维，可以把它想成虚拟机模板；如果你是开发者，可以把它想成类（class）。 

$ docker images
REPOSITORY   TAG   IMAGE ID   CREATED   SIZE

全新安装的 Docker 一个镜像都没有。把镜像复制到本机叫做拉取（pull）。拉取最新的 NGINX Web 服务器镜像：

$ docker pull nginx:latest
latest: Pulling from library/nginx
ad5932596f78: Download complete
e4bc5c1a6721: Download complete
1bd52ec2c0cb: Download complete
<Snip>
Digest: sha256:fb197595ebe76b9c0c14ab68159fd3c08bd067ec62300583543f0ebda353b5be
Status: Downloaded newer image for nginx:latest
docker.io/library/nginx:latest

$ docker images
REPOSITORY   TAG      IMAGE ID       CREATED       SIZE
nginx        latest   fb197595ebe7   10 days ago   280MB

镜像存在哪、里面有什么，第 6 章会细讲。现在只需知道：这个 NGINX 镜像里有一个精简版 Linux 和 NGINX Web 服务器程序。 那几行 Download complete 各对应一个镜像层，这也是第 6 章的重点。

③ 从镜像启动一个容器

$ docker run --name test -d -p 8080:80 nginx:latest
e08c3535...30557225

返回的一长串字符是新容器的 ID，说明容器创建成功了。这条命令是整本教程最重要的命令，我们把它拆开看：

其中 -p 8080:80 最容易搞混方向，记住口诀：“左主右容” —— 冒号左边是宿主机端口，右边是容器内端口。

现在打开浏览器访问 http://localhost:8080，你会看到 Welcome to nginx!。再用 docker ps 看看正在运行的容器：

$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED      STATUS      PORTS                  NAMES
e08c35352ff3   nginx:latest   "/docker-entrypoint.…"   3 mins ago   Up 2 mins   0.0.0.0:8080->80/tcp   test

CONTAINER ID 就是刚才那一长串 ID 的前 12 位；IMAGE、PORTS、NAMES 都和 docker run 里的参数一一对应； COMMAND 是 Docker 在容器里启动 NGINX 所执行的命令。

④ 在容器里执行命令

用 docker exec 在容器里启动一个新的 Bash 进程，并把你的终端连上去：

$ docker exec -it test bash
root@e08c35352ff3:/# ls -l
total 64
lrwxrwxrwx   1 root root    7 Jan  2 00:00 bin -> usr/bin
drwxr-xr-x   2 root root 4096 Oct 31 11:04 boot
drwxr-xr-x   5 root root  340 Jan 12 15:09 dev
-rwxr-xr-x   1 root root 1620 Jan  3 02:56 docker-entrypoint.sh
drwxr-xr-x   1 root root 4096 Jan 12 15:09 etc
<Snip>
root@e08c35352ff3:/# ps -elf
bash: ps: command not found

提示符变成了 root@e08c35352ff3:/#，说明你已经“在容器里”了。ls 能看到熟悉的 Linux 目录结构， 但 ps 命令竟然不存在！这是有意为之：大多数镜像只包含运行应用必需的程序， 这样镜像更小、攻击面更少。第 7 章会教你用 Docker Debug 在这种“什么工具都没有”的容器里排查问题。

输入 exit 退出 Bash 进程，回到你本地的终端。再运行 docker ps，容器依然在运行 —— 因为你退出的只是 bash，不是 nginx 主进程。

⑤ 停止并删除容器

$ docker stop test      # 优雅停止，可能需要几秒
test
$ docker rm test        # 删除
test
$ docker ps -a          # -a 显示所有容器，包括已停止的
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

恭喜！你已经完成了拉取镜像 → 启动容器 → 进入容器执行命令 → 停止并删除容器的完整流程。

💡 新旧两套命令写法

Docker 的命令有两种写法：老的“短命令”如 docker ps、docker images、docker rmi， 和新的“管理命令”如 docker container ls、docker image ls、docker image rm。两者完全等价。 本教程主要用更常见的短命令，但你在官方文档里会经常看到管理命令。

开发视角：把代码变成容器

容器的一切都是为了应用。这一部分你将：从 GitHub 克隆一个应用 → 查看它的 Dockerfile → 把它容器化 → 作为容器运行。

克隆应用代码

$ git clone https://github.com/nigelpoulton/psweb.git
Cloning into 'psweb'...
<Snip>
$ cd psweb
$ ls -l
-rw-r--r--  1 nigel  staff  324  Dockerfile
-rw-r--r--  1 nigel  staff  378  README.md
-rw-r--r--  1 nigel  staff  341  app.js
-rw-r--r--  1 nigel  staff  355  package.json
drwxr-xr-x  3 nigel  staff   96  views

这是一个很简单的 Node.js Web 应用，提供一个静态 HTML 页面。

查看 Dockerfile

Dockerfile 是一个纯文本文件，告诉 Docker 如何把应用和依赖构建成镜像。

FROM alpine
LABEL maintainer="nigelpoulton@hotmail.com"
RUN apk add --update nodejs npm curl
COPY . /src
WORKDIR /src
RUN npm install
EXPOSE 8080
ENTRYPOINT ["node", "./app.js"]

第 8 章会逐条详解。现在你只需知道每一行都是 Docker 构建镜像时要执行的一条指令，大意是：

指令通俗解释
FROM alpine以 Alpine Linux（一个只有几 MB 的精简发行版）为基础
LABEL ...贴个标签，记录维护者（只是元数据）
RUN apk add ...在镜像里安装 Node.js、npm 和 curl
COPY . /src把当前目录的代码复制到镜像的 /src
WORKDIR /src后续指令都在 /src 目录下执行
RUN npm install安装应用依赖
EXPOSE 8080声明应用监听 8080 端口（文档作用）
ENTRYPOINT [...]容器启动时执行 node ./app.js

容器化应用

在 psweb 目录里运行下面的命令，别漏了最后那个点 —— 它表示“用当前目录作为构建上下文”：

$ docker build -t test:latest .
[+] Building 36.2s (11/11) FINISHED
 => [internal] load build definition from Dockerfile            0.0s
 => [internal] load .dockerignore                               0.0s
 <Snip>
 => => naming to docker.io/library/test:latest                  0.0s

$ docker images
REPOSITORY   TAG      IMAGE ID       CREATED          SIZE
test         latest   0435f2738cf6   21 seconds ago   160MB

恭喜，你已经把应用容器化了 —— 这是行话，意思就是把应用和所有依赖构建成一个容器镜像。

作为容器运行

$ docker run -d \
  --name web1 \
  --publish 8080:8080 \
  test:latest

--publish 是 -p 的完整写法。在浏览器打开 http://localhost:8080（如果用 Multipass，换成虚拟机的 192.168.x.x 地址）， 就能看到这个应用的页面了。

ⓘ Windows 用户注意

上面的反斜杠 \ 是 Linux/macOS shell 的续行符。PowerShell 里要换成反引号 `，或者干脆写成一行。

清理

$ docker rm web1 -f          # -f 强制删除运行中的容器（跳过 stop）
web1
$ docker rmi test:latest     # rmi = remove image
Untagged: test:latest
Deleted: sha256:0435f27...cac8e2b

本章小结

  • 运维视角：你拉取了镜像、从它启动了容器、进入容器执行了命令，最后停止并删除了容器。
  • 开发视角：你从 GitHub 拿到源码，用 Dockerfile 里的指令把它构建成镜像，再作为容器运行。
  • -p 主机端口:容器端口，“左主右容”。
  • 镜像通常只包含运行应用所必需的东西，所以很多常用命令在容器里不存在是正常的。
