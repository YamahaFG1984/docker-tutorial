第 1 章

容器的前世今生

在学任何 Docker 命令之前，先搞清楚一个问题：我们为什么需要容器？ 答案藏在过去二十年服务器的演化史里 —— 从“一台服务器只跑一个应用”，到虚拟机，再到容器。

本章目标

  • 理解“一台服务器一个应用”时代的浪费问题
  • 说清虚拟机解决了什么、又带来了什么新问题
  • 理解容器为什么比虚拟机更轻、更快、更便携
  • 知道 Windows 容器、Linux 容器、Mac 上的容器分别是怎么回事
  • 对 Wasm、AI、Kubernetes 与 Docker 的关系有个初步印象

过去：一台服务器一个应用

应用程序是现代企业的发动机：应用一挂，生意就停。而应用都跑在服务器上。

在很长一段时间里，我们一台服务器只能跑一个应用。原因很简单：几个应用挤在同一个操作系统里， 它们会抢同一个端口、依赖同一个库的不同版本、一个崩了可能把另一个拖下水。所以最稳妥的做法是：每上线一个新应用，就买一台新服务器。

问题是，没人能准确预估一个新应用需要多少性能。买小了，应用扛不住，客户流失；买大了，只是浪费钱。 于是大家都选择“宁大勿小”，结果机房里堆满了利用率只有 5%–10% 的昂贵服务器。

虚拟机来了

就在这时，VMware 公司带来了虚拟机（VM）。虚拟机技术让我们可以在一台物理服务器上安全地运行多个应用： 一个叫 Hypervisor（虚拟机管理程序） 的软件把物理服务器的 CPU、内存、磁盘、网卡“切”成好几份虚拟的， 每份打包成一台看起来和真服务器一模一样的虚拟机，然后在每台虚拟机里装操作系统、装应用。

这是一次革命。企业可以把新应用部署到现有服务器的空闲资源上，不用再每次都买新机器。

虚拟机的烦恼

虚拟机很好，但远不完美。它最大的问题是：每台虚拟机都需要一个完整的操作系统。这意味着：

  • 每个操作系统都要吃资源。CPU、内存、磁盘被操作系统本身占掉一大块，而这些资源我们本来想留给应用。
  • 每个操作系统都要打补丁。100 台虚拟机 = 100 个要维护、要升级、要打安全补丁的系统。
  • 每个操作系统都要监控。运维的工作量随虚拟机数量线性增长。
  • 启动慢。开一台虚拟机要经历完整的操作系统启动流程，通常以分钟计。
  • 不便携。虚拟机镜像动辄几个 GB 到几十 GB，想从一个平台搬到另一个平台很麻烦。

我们把这些额外开销叫做“虚拟机税”。

容器来了

当大多数公司还在享受虚拟机红利时，Google 这样的超大规模互联网公司早已转向了容器。

容器模型最关键的一点是：所有容器共享宿主机的操作系统（准确地说，是共享宿主机的内核）。 每个容器里只装应用和它的依赖，不需要自己的操作系统。所以同一台主机上，能跑的容器数量远远多于虚拟机 —— 一台能跑 10 台虚拟机的主机，可能能跑 50 个容器。

共享宿主机操作系统带来了一串好处：

虚拟机容器
体积几 GB 到几十 GB（含完整 OS）几 MB 到几百 MB（只含应用和依赖）
启动时间分钟级（要启动整个 OS）秒级甚至毫秒级（OS 已经在跑了）
密度一台主机跑几台到几十台一台主机跑几十到几百个
要维护的 OS 数量每台 VM 一个整台主机只有一个
隔离强度强（每台 VM 有独立内核）较弱（共享内核），需要额外安全技术加固
ⓘ 共享内核是把双刃剑

所有容器共享宿主机内核，这带来了性能和便携性，但也意味着：如果某个恶意容器利用了内核漏洞，理论上可能影响同一台主机上的其他容器。 好在今天的容器平台都默认启用了 SELinux/AppArmor、seccomp、capabilities 等安全技术（第 16 章会讲）， 再加上镜像漏洞扫描，容器的安全性已经可以做得非常好。今天，绝大多数新应用都首选容器。

Linux 容器与 Docker

现代容器技术诞生于 Linux 世界，是很多人多年努力的结晶。比如 Google 就向 Linux 内核贡献了大量和容器相关的技术。 支撑容器的几项核心内核技术是：

🧱

命名空间 namespaces

负责隔离：让每个容器以为自己独占进程树、网络、文件系统、主机名。

📏

控制组 cgroups

负责限制：规定每个容器最多能用多少 CPU、内存、磁盘 I/O。

🔑

能力 capabilities

负责降权：把 root 的超级权限拆成几十个小权限，只给容器需要的那几个。

但问题是，这些技术在很长时间里极其复杂，只有少数专家会用。直到 2013 年 Docker 出现， 它用一条简单的 docker run 命令和对开发者友好的工作流，把容器带给了所有人。

Windows、Mac 与容器

理解容器时有一条最重要的规则：容器共享宿主机的内核。由此可以直接推出：

  • 容器化的 Linux 应用需要一个 Linux 内核来运行；
  • 容器化的 Windows 应用需要一个 Windows 内核来运行。

那 Mac 和 Windows 电脑上怎么跑 Linux 容器呢？答案是：在后台悄悄开一台轻量的 Linux 虚拟机。

  • Windows：Windows 10/11 和所有现代 Windows Server 都原生支持 Windows 容器。 同时它们还能通过 WSL 2（Windows Subsystem for Linux）运行 Linux 容器，所以 Windows 电脑是开发 Linux 容器的好平台。
  • Mac：世界上没有“Mac 容器”。但 Mac 是非常好的容器开发平台：Docker Desktop 会在 Mac 上运行一个轻量 Linux 虚拟机， Docker 就跑在这台虚拟机里。Podman Desktop、Rancher Desktop、OrbStack、Colima 等工具也是同样的思路。

尽管 Windows 容器投入了大量研发，但现实中几乎所有容器都是 Linux 容器 —— 更小、更快、工具更丰富。 本教程的所有示例也都是 Linux 容器。

💡 术语：容器化应用

容器化应用（containerized app）指的就是“以容器形式运行的应用”。把一个应用变成这样的过程叫容器化（containerize），第 8 章会详细讲。

Wasm 又是什么？

Wasm（WebAssembly）是一种现代的二进制指令格式。你用喜欢的语言写程序，编译成 Wasm 二进制文件， 它就能在任何有 Wasm 运行时的地方运行 —— 而且比容器更小、更快、更安全、更便携。

不过 Wasm 应用目前限制还很多，很多标准仍在制定中，生态也远不如容器成熟。所以容器依然是云原生应用的主流形态。 未来更可能的局面是：虚拟机、容器、Wasm 在同一朵云里并存，各自干自己最擅长的事。

✨ 最新变化：Docker Desktop 的 Wasm 功能已弃用

原书用一整章（本教程第 11 章）讲 Docker + Wasm。但在 2025 年之后，Docker 官方已将 Docker Desktop 中的 Wasm workloads 功能标记为弃用（deprecated），不再积极维护，并会在未来版本中移除。 Wasm 技术本身仍在发展（比如 Spin、wasmtime、WASI 0.2），只是 Docker Desktop 不再是运行它的推荐方式。第 11 章会详细说明。

Docker 与 AI

开发者和企业正在使用越来越多的 AI 应用，而 Docker 连续多年在 Stack Overflow 开发者调查中被评为最常用、最想用的开发工具。

但让容器里的程序访问 GPU 等 AI 加速硬件非常困难：每家硬件厂商都有自己的驱动和 SDK，整个行业不可能为每一种都做容器适配。 所以 Docker 推出了 Docker Model Runner（DMR）：在容器之外直接在宿主机上运行本地大模型， 让模型能直接用上宿主机的硬件，同时又和 Docker 的工具链（CLI、Compose、Docker Hub）无缝集成。第 10 章会专门讲它。

✨ 最新变化：Model Runner 已经走出 Docker Desktop

原书写作时 DMR 还是 Docker Desktop（Mac / Windows）的实验功能。到 2026 年，DMR 已经支持 Linux 上的 Docker Engine， 后端除了 llama.cpp 还有 vLLM（高吞吐）和 Diffusers（图像生成）， 并同时提供 OpenAI、Anthropic、Ollama 兼容的 API。

那 Kubernetes 呢？

Kubernetes 是部署和管理容器化应用的行业标准平台。你可以把它理解成“管理成百上千个容器的操作系统”。

早期版本的 Kubernetes 用 Docker 来启动和停止容器，而新版本改用了 containerd —— 它是从 Docker 中拆分出来的、专门为 Kubernetes 等平台优化过的精简运行时（第 5 章详细讲）。

★ 你只需要记住

用 Docker 构建的镜像，可以直接在 Kubernetes 上运行。因为它们都遵循同一套 OCI 标准（第 2 章）。 学好 Docker，就是学 Kubernetes 最好的起点。

本章小结

  • 过去每个应用都要一台专用的、性能过剩的服务器，浪费严重。
  • 虚拟机让一台服务器能安全地跑多个应用，但每台虚拟机都要一个完整操作系统，这就是“虚拟机税”。
  • 容器共享宿主机内核，因此更小、更快、更便携；但早期容器技术非常复杂，直到 Docker 出现才让它变得简单。
  • Linux 容器需要 Linux 内核，Windows 容器需要 Windows 内核；Mac 和 Windows 通过后台的 Linux 虚拟机运行 Linux 容器。
  • Wasm 和 AI 是新的方向，Docker 生态也在围绕它们演进；Docker 镜像可以直接跑在 Kubernetes 上。
