第 11 章

Docker 与 Wasm Desktop 功能已弃用

WebAssembly（Wasm）被称为云计算的“第三波”：第一波建立在虚拟机上，第二波建立在容器上，第三波正在 Wasm 上展开。 本章写一个简单的 Wasm Web 应用，把它打包成 OCI 镜像，并作为“Wasm 容器”运行 —— 同时也会告诉你，这条路在 Docker Desktop 上已经走到尽头。

⚠ 先读这里：Docker Desktop 的 Wasm 功能已被弃用

原书写作时（2025 年 5 月），Wasm 支持是 Docker Desktop 的 Beta 功能。此后 Docker 官方已将 Wasm workloads 标记为弃用（deprecated）： 不再积极维护，并将在未来的 Docker Desktop 版本中移除。

所以本章的定位是：理解 Wasm 的概念，以及“容器运行时可以被替换”这一重要思想（回顾第 5 章的 shim）。 动手部分可以在仍保留该功能的 Docker Desktop 上尝试，但不要把它用于新的生产设计。想在生产中用 Wasm，可以直接使用 Spin / wasmtime 等运行时， 或在 Kubernetes 上用 SpinKube、containerd 的 runwasi shim。

本章目标

  • 理解 Wasm 是什么，它和容器相比的优势与局限
  • 理解“Wasm 容器”的原理：scratch 镜像 + .wasm 文件 + 替换 runc 的 Wasm 运行时
  • 用 Spin 写一个 Rust Web 应用并编译成 Wasm
  • 用 --platform wasi/wasm 构建镜像，用 --runtime 运行它

云计算的三波浪潮

Wasm 与 Wasm 容器

Wasm 是一种新的虚拟机指令集架构，编程语言可以把程序编译成它。也就是说，你不再把应用编译成“Linux on ARM”或“Linux on AMD”， 而是编译成 Wasm，然后它就能在任何装有 Wasm 运行时的系统上运行。

传统 Linux 容器Wasm 应用
体积MB 到数百 MBKB 到几 MB
启动秒级毫秒级（适合 Serverless 冷启动）
可移植性需要为每种 CPU 架构构建一个二进制到处运行
安全模型共享内核 + 各种加固默认拒绝的沙箱，能力需显式授予
擅长几乎一切AI 推理、Serverless 函数、插件、边缘设备
不擅长—复杂网络、重 I/O（标准仍在完善，如 WASI 0.2 / 0.3）

Wasm 容器就是把一个 Wasm 二进制放进一个最小的 scratch 镜像里运行，这样就能用 docker build、docker run、Docker Hub 这些熟悉的工具来构建、分发和运行它。 关键在于：containerd 不再调用 runc，而是通过 shim 调用一个 Wasm 运行时：

准备工作

如果要动手，需要：

  • 仍然提供 Wasm 功能的 Docker Desktop（原书在 4.37 上测试），并启用 Wasm；
  • Rust 1.82+，并安装 Wasm 编译目标；
  • Spin 3.1+。

配置 Docker Desktop

打开 Docker Desktop 设置：在 General 页确认勾选了 Use containerd for pulling and storing images； 在 Features in development 页勾选 Enable Wasm，然后点击 Apply & restart。 Wasm 功能不支持 Multipass 等其他 Docker 环境。

安装 Rust 和 Wasm 编译目标

# 先按 https://rustup.rs 的说明安装 Rust，然后：
$ rustup target add wasm32-wasip1
info: downloading component 'rust-std' for 'wasm32-wasip1'
info: installing component 'rust-std' for 'wasm32-wasip1'

安装 Spin

Spin 是一个让构建和运行 Wasm 应用变得简单的框架和运行时（最初由 Fermyon 创建，现为 CNCF 项目）。按官方文档安装后验证：

$ spin --version
spin 3.1.0 (1aa89da 2024-12-18)

Docker Desktop 自带了多个 Wasm 运行时（shim），可以这样查看：

$ docker run --rm -i --privileged --pid=host jorgeprendes420/docker-desktop-shim-manager:latest

io.containerd.slight.v1

编写 Wasm 应用

用 spin 创建一个叫 hello-world 的 Rust Web 应用，按提示输入：

$ spin new hello-world -t http-rust
Description: Wasm app
HTTP path: /hello

$ cd hello-world
$ tree
.
├── Cargo.toml
├── spin.toml
└── src
    └── lib.rs

编辑 src/lib.rs，把引号里的文字改成 Docker loves Wasm：

use spin_sdk::http::{IntoResponse, Request, Response};
use spin_sdk::http_component;

#[http_component]
fn handle_hello_world(req: Request) -> anyhow::Result<impl IntoResponse> {
    Ok(Response::builder()
        .status(200)
        .header("content-type", "text/plain")
        .body("Docker loves Wasm")      // ← 改这里
        .build())
}

把应用编译成 Wasm 二进制：

$ spin build
Building component hello-world with `cargo build --target wasm32-wasip1 --release`
<Snip>
Finished building all Spin components

$ tree target
target
└── wasm32-wasip1
    └── release
        └── hello_world.wasm        <<---- 这就是 Wasm 应用

先用本地安装的 spin 运行时测试一下：

$ spin up
Serving http://127.0.0.1:3000
Available Routes:
  hello-world: http://127.0.0.1:3000/hello

浏览器访问 http://127.0.0.1:3000/hello，看到 “Docker loves Wasm” 就成功了。按 Ctrl+C 停止。

容器化 Wasm 应用

和往常一样，需要一个 Dockerfile。在当前目录创建它：

FROM scratch
COPY /target/wasm32-wasip1/release/hello_world.wasm .
COPY spin.toml .

FROM scratch 表示从空镜像开始 —— Wasm 容器不需要 Linux 操作系统。两条 COPY 把 Wasm 应用和 spin.toml 复制到镜像根目录。 但 spin.toml 里写的 Wasm 文件路径还是 target/wasm32-wasip1/release/，所以要改成根目录： 

[component.hello-world]
source = "hello_world.wasm"      # 去掉前面的目录，只保留文件名

构建镜像（请换成你自己的 Docker Hub 用户名）：

$ docker build \
    --platform wasi/wasm \
    --provenance=false \
    -t nigelpoulton/ddd-book:wasm .

$ docker images
REPOSITORY              TAG    IMAGE ID       CREATED          SIZE
nigelpoulton/ddd-book   wasm   7b55889f1006   28 seconds ago   104kB

--platform wasi/wasm 把镜像标记为 Wasm 镜像。它看起来就是个普通镜像，只是小得惊人（104KB）。你可以像平常一样推送到 Docker Hub： 

$ docker push nigelpoulton/ddd-book:wasm

在 Docker Hub 上会看到它被识别为 wasi/wasm 镜像，而且没有漏洞分析数据 —— 镜像扫描工具还不能分析 Wasm 镜像。

运行 Wasm 容器

$ docker run -d --name wasm-ctr \
    --runtime=io.containerd.spin.v2 \
    --platform=wasi/wasm \
    -p 5556:80 \
    nigelpoulton/ddd-book:wasm /

--runtime 让 Docker 用 spin Wasm 运行时来执行这个容器（而不是 runc）。用 docker ps 确认它在运行，然后访问 http://localhost:5556/hello。

清理

$ docker rm wasm-ctr -f
$ docker rmi nigelpoulton/ddd-book:wasm

Docker Hub 上的镜像和本地的 spin 项目也可以按需删除。

Wasm 之后去哪里？

直接用 Spin / wasmtime

不经过 Docker，直接在服务器或边缘节点上运行 Wasm 应用。

Kubernetes + SpinKube

在 K8s 中用 containerd 的 runwasi shim 调度 Wasm 工作负载，和普通 Pod 混部。

边缘平台

Fastly、Cloudflare Workers 等边缘平台原生运行 Wasm。

OCI 分发仍然适用

Wasm 模块依旧可以作为 OCI 制品存进你的镜像仓库。

本章小结

  • Wasm 是一种新的虚拟指令集：一次编译、到处运行，比传统容器更小、更快、更安全，但目前不擅长重 I/O 和复杂网络。
  • “Wasm 容器”= scratch 镜像 + .wasm 文件 + 替代 runc 的 Wasm 运行时 shim，因此能沿用 docker build/push/run。
  • 构建时用 --platform wasi/wasm，运行时用 --runtime=io.containerd.spin.v2。
  • Docker Desktop 的 Wasm 功能已被弃用；Wasm 生态本身仍在快速发展，可以通过 Spin、SpinKube、边缘平台等方式继续使用。
