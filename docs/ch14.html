第 14 章

Overlay 网络

真实世界的容器需要一种可靠、安全的通信方式，而且不关心自己跑在哪台主机上、那台主机又连在哪个网络上。 这正是 overlay 网络的用武之地：它创建一个扁平、安全、横跨多台主机的二层网络，不同主机上的容器连到同一个 overlay 网络就能直接通信。

本章目标

  • 理解 overlay 网络解决的问题：跨主机的容器通信
  • 动手创建加密的 overlay 网络并验证跨主机连通
  • 理解 underlay（底层网络）与 overlay（覆盖网络）的关系
  • 理解 VXLAN、VTEP、VNID 以及一个数据包的完整旅程

一句话概括

Docker 提供原生的 overlay 网络，配置简单、默认安全。它构建在 libnetwork（CNM 的标准实现）和原生的 overlay 驱动之上， 后者实现了构建 overlay 网络的所有机制。

Overlay 网络的由来

2015 年 3 月，Docker 公司收购了一家叫 SocketPlane 的容器网络初创公司，目标有两个：

  1. 给 Docker 带来 overlay 网络；
  2. 让容器网络对开发者来说足够简单。

两个目标都实现了。但简单的 Docker 命令背后藏着大量复杂性。如果你只是偶尔用用 Docker，知道命令就够了； 但如果要在生产环境中用 Docker，特别是用 Swarm 和 Docker 网络，本章的内容就非常关键。

动手：创建并测试 overlay 网络

你需要至少两个组成 swarm 的 Docker 节点（overlay 网络依赖 swarm 的键值存储和其他安全功能）。 书中示例的两个节点位于由路由器连接的不同网络上，你的节点也可以在同一网络上，只是底层网络更简单而已。 用同一台电脑上的两个 Multipass 虚拟机，或者 Play with Docker 都可以。不建议用 Docker Desktop，因为只有一个节点。

搭建 swarm

确保两个节点之间开放了这些端口：

  • 2377/tcp：管理平面通信；
  • 7946/tcp 和 7946/udp：控制平面通信（基于 SWIM 的 gossip）；
  • 4789/udp：VXLAN 数据平面。
node1 $ docker swarm init
Swarm initialized: current node (1ex3...o3px) is now a manager.

node2 $ docker swarm join --token SWMTKN-1-0hz2ec...2vye 172.31.1.5:2377
This node joined a swarm as a worker.

现在 node1 是管理节点，node2 是工作节点。

创建 overlay 网络

在管理节点 node1 上创建一个加密的 overlay 网络 uber-net：

$ docker network create -d overlay -o encrypted uber-net
vdu1yly429jvt04hgdm0mjqc6

$ docker network ls
NETWORK ID     NAME              DRIVER    SCOPE
65585dda7500   bridge            bridge    local
7e368a1105c7   docker_gwbridge   bridge    local
a38083cdab1c   host              host      local
4dsqo7jc36ip   ingress           overlay   swarm
d97e92a23945   none              null      local
vdu1yly429jv   uber-net          overlay   swarm     <<---- 新的 overlay 网络

就这样，一个全新的加密 overlay 网络建好了。它横跨 swarm 中的两个节点，SCOPE 是 swarm。 Docker 会加密它（AES-GCM），并且每 12 小时轮换一次加密密钥。

✨ 更正原书：数据平面加密用的是 IPsec

原书说 overlay 网络用 TLS 加密。准确地说：控制平面（管理流量）默认就用 TLS 加密； 数据平面（应用流量）只有加了 -o encrypted 才加密，用的是 IPsec 隧道（AES-GCM 模式），密钥每 12 小时轮换。 加密数据平面大约会带来 10% 的性能损失。注意：Windows 节点不支持加密的 overlay 网络。

如果你在 node2 上列出网络，看不到 uber-net。这是因为 Docker 只在工作节点需要时才把 overlay 网络扩展过去， 这种“懒加载”减少了 swarm 中的网络 gossip 流量，提升了可扩展性。

把容器接入 overlay 网络

默认情况下，只有 swarm 服务的容器才能接入 overlay 网络。如果想接入独立容器（docker run 启动的），创建网络时要加 --attachable。 下面创建一个有 2 个副本的服务 test，Swarm 会把副本分别放到两个节点上，从而让 Docker 把网络扩展到 node2： 

$ docker service create --name test \
    --network uber-net \
    --replicas 2 \
    ubuntu sleep infinity

$ docker service ps test
ID          NAME     IMAGE           NODE    DESIRED STATE   CURRENT STATE
sm1...1nw   test.1   ubuntu:latest   node1   Running         Running
tro...kgk   test.2   ubuntu:latest   node2   Running         Running

现在到 node2 上运行 docker network ls，就能看到 uber-net 了。

Overlay 网络原理

VXLAN 入门

首先，Docker 用 VXLAN 隧道创建虚拟的二层 overlay 网络。从最高层看，VXLAN 让你在现有的三层基础设施之上创建二层网络 —— 说人话就是：在复杂的网络之上创建简单的网络。前面的例子就是在一个复杂的网络拓扑之上，建了一个新的 10.0.0.0/24 二层网络。

ⓘ 术语

我们用 underlay 网络（底层网络）或 underlay 基础设施来指 overlay 隧道所穿越的那些网络。

VXLAN 是一种封装技术，所以对现有路由器和网络设备是透明的：底层网络中的路由器等设备把 VXLAN/overlay 流量看成普通的 IP/UDP 包，不需要任何改动。 为了创建 overlay，Docker 会穿过底层网络建立一条 VXLAN 隧道，overlay 流量就在这条隧道里自由流动，而不必和底层网络的复杂性打交道。

隧道的两端各由一个 VTEP（VXLAN Tunnel Endpoint，VXLAN 隧道端点）终结，由它负责对进出隧道的流量进行封装和解封装。 图中把底层网络画成一朵“云”有两个原因：它可能比两个网段加一个路由器复杂得多；而且 VXLAN 隧道把这种复杂性抽象掉了，对上层来说是不透明的。

幕后搭建了什么

前面动手时两台主机通过 IP 网络相连，你在上面建了 overlay 网络、接入两个容器、做了 ping 测试。幕后发生了这些事：

  1. Docker 在每台主机上创建一个新的沙箱（网络命名空间），里面有一个叫 Br0 的虚拟交换机；
  2. 创建一个 VTEP，一端连在 Br0 上，另一端连在主机的网络栈上。主机网络栈这一端获得底层网络上的 IP，并绑定 UDP 4789 端口；
  3. 两台主机上的 VTEP 建立一条 VXLAN 隧道，作为 overlay 网络的骨干；
  4. 接入容器时，Docker 在每个容器里创建一个虚拟网卡（veth），并把它连到本地的 Br0 虚拟交换机上。

一个数据包的旅程

⚠ 这一节很硬核

日常运维不需要完全理解这部分。但当你需要和网络团队沟通，或者排查诡异的跨主机网络问题时，它会非常有用。

假设 node1 上的 C1（10.0.0.3）要 ping node2 上的 C2（10.0.0.4）：

  1. C1 发出 ping：C1 的 MAC 地址表（ARP 缓存）里没有 10.0.0.4，于是在所有接口上泛洪，包括连到 Br0 的 veth。
  2. Br0 代答 ARP：Br0 知道发往 10.0.0.4 的流量应该交给连接的 VTEP，于是回复一个代理 ARP。veth 学会了以后把发往 10.0.0.4 的包直接送给本地 VTEP。 Br0 之所以知道 C2，是因为 Docker 通过网络内置的 gossip 协议，把所有新容器的信息传播给了每个 swarm 节点。
  3. VTEP 封装：veth 把 ping 包交给 VTEP，VTEP 加上一个 VXLAN 头，其中包含 VNID（VXLAN 网络 ID），用来区分不同的 overlay 网络、保持隔离； 再把整个帧包进一个 UDP 包，目的 IP 填 node2 上 VTEP 的地址，目的端口是 UDP 4789。这样包就能在底层网络中路由，而底层网络对 VXLAN 一无所知。
  4. node2 解封装：包到达 node2，内核发现它发往 UDP 4789，而这个端口绑定着一个 VTEP，于是把包交给 VTEP。 VTEP 读取 VNID、解封装，把原始帧交给本地对应的 Br0，最终送到 C2。

这就是 Docker 用 VXLAN 构建和运行 overlay 网络的方式 —— 一大堆让人头大的复杂性，被优雅地藏在了一条 Docker 命令后面。 作者的忠告：别以为读完这一节就懂了 VXLAN 的全部，然后跑去跟网络团队高谈阔论 —— 多半会出糗，他是过来人 ;-)

overlay 网络中的三层路由

Docker 还支持在一个 overlay 网络内部做三层路由。比如下面的命令创建一个有两个子网的 overlay 网络，Docker 会自动在沙箱里创建 Br0 和 Br1 两个虚拟交换机并处理路由：

$ docker network create --subnet=10.1.1.0/24 --subnet=11.1.1.0/24 -d overlay prod-net

清理

$ docker service rm test
$ docker network rm uber-net      # 可能要等几秒，等服务删干净
# 不再需要 swarm 的话，在两个节点上执行（先 node2）：
$ docker swarm leave -f

命令速查

命令作用
docker network create -d overlay 名称创建 overlay 网络；-o encrypted 加密数据平面（约 10% 性能损失），--attachable 允许独立容器接入
docker network ls列出网络。swarm 模式下，工作节点只在运行了相关容器时才看得到 overlay 网络
docker network inspect 名称查看范围、驱动、子网、本节点上容器的 IP、VXLAN ID、加密状态等
docker network rm 名称删除网络

本章小结

  • overlay 网络创建扁平、安全、横跨多台主机的二层网络，不同主机上的容器可以直接通信。
  • Docker 的 overlay 网络基于 libnetwork 和 overlay 驱动，依赖 swarm 模式；网络只在需要时才扩展到工作节点。
  • 控制平面默认加密；数据平面加 -o encrypted 后用 IPsec 加密。
  • 底层原理是 VXLAN：VTEP 把容器的二层帧封装进 UDP 4789 的包里穿越底层网络，VNID 保证不同 overlay 网络之间的隔离。
