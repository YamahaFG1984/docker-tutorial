为什么要学 Docker？

你一定听过这句话：“在我电脑上明明是好的啊！” 开发者的笔记本上装的是 Node 22，测试服务器上是 Node 18；本地用的是 macOS，线上跑的是 Ubuntu； 某个依赖库在一台机器上有、另一台机器上没有……这些差异让“把程序从一台机器搬到另一台机器”变成了一件痛苦的事。

Docker 的解决办法非常朴素：把程序连同它需要的一切（运行时、库、配置、文件）打成一个包，这个包叫镜像。 镜像在任何装了 Docker 的机器上运行起来都一模一样，运行起来的那个东西叫容器。

这套教程写给谁

  • 完全没接触过容器的人。第 1–4 章从“为什么需要容器”讲起，第 4 章就能跑起第一个容器。
  • 会用几条 docker 命令，但说不清原理的人。第 5–8 章会拆开引擎、镜像分层、容器读写层和构建缓存。
  • 需要把项目容器化并上线的开发者。Dockerfile 最佳实践、多阶段构建、Compose、网络、卷、安全都有专章。
  • 想在本地跑大模型的人。第 10 章用 Docker Model Runner 拉模型、调 API、接入 Compose。
  • 要在团队里真正用起来的人。第 17–23 章讲排错、用容器搭开发环境、用 GitHub Actions 搭镜像流水线、部署到服务器、各语言的生产级 Dockerfile，一次真实测量的镜像瘦身实验，以及从 Compose 迁移到 Kubernetes。
ⓘ 需要什么前置知识

会在终端里敲命令（cd、ls）就够了。不需要会 Linux 运维，不需要会任何特定编程语言 —— 示例里出现的 Node.js、Python、Go 代码都很短，我们只关心“怎么把它装进容器”，不关心代码本身。

怎么用这套教程

  • 按顺序读。第 1–9 章是主线，建议顺序阅读；第 10–16 章相对独立，可以按需跳读；第 17–23 章是实战篇（排错、开发环境、CI/CD、部署、各语言 Dockerfile、镜像瘦身、迁移到 Kubernetes），学完主线后随时回来查。
  • 亲手敲命令。每章都有可以直接复制的命令（点代码块右上角的“复制”，会自动去掉 $ 提示符）， 每章末尾还有「动手练习」。
  • 看图。Docker 的很多概念（分层、网络、卷）用文字解释很抽象，画出来一眼就懂。每张图都值得停下来多看几秒。
  • 留意提示框的颜色： 蓝色 · 说明 绿色 · 技巧 红色 · 警告 橙色 · 重点 紫色 · 深入 / 最新变化

★ 一句话总结

如果你只记住一件事：镜像是只读的“模板”，容器是从模板启动的“实例”； 容器本质上是一个被 Linux 内核隔离和限制起来的普通进程。 这套教程剩下的内容，都是在解释这句话的各种展开。
